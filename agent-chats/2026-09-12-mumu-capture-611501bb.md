## 1. 需求 & 关键决策

| 决策点 | 选择 | 备注 |
|---|---|---|
| 分支起点 | `upstream/v1.44` → `tinecmatool/mumu` | 曾短暂叠 TinecmaTool branding，后 `reset --hard v1.44` 清掉 |
| 本机官方 MSI | v1.43 | 与 1.44 源码对照时注意版本差 |
| Secure Boot | 开启 | AppInit 全局钩子对本机 GUI 进程基本失效（官方 signed shim 同样不行） |
| 捕获目标进程 | `MuMuVMMHeadless.exe` | `MuMuPlayer.exe` 只是前端启动器，无图形设备 |
| Launch 路径 | 启动 MuMu 前装全局 shim，再等 Headless 加载 DLL | 绕开“注入到错误进程” |
| Global Hook UI | 选 MuMuPlayer 时匹配名改写为 Headless | 与 Launch 行为一致 |

## 2. 改动文件

| 文件 | 作用 |
|---|---|
| `renderdoc/os/win32/win32_process.cpp` | `LaunchAndInjectIntoProcess`：若目标为 `MuMuPlayer.exe`，先 `StartGlobalHook(MuMuVMMHeadless.exe)`，启动前端，轮询 Headless 并 `ConfigureLoadedRenderDocProcess`；另补 `RDOC_BASE_NAME` 缺省、`IsGlobalHookDataReady` / `FindProcessIdByName` |
| `qrenderdoc/Windows/Dialogs/CaptureDialog.cpp` | Global Hook 对 `MuMuPlayer.exe` 改用 `MuMuVMMHeadless.exe` 作为 match |
| `renderdoccmd/renderdoccmd_win32.cpp` | `GetModuleHandle` 走 `RDOC_BASE_NAME`；避免 `shellapi.h` 宏撞 `ShellExecute` |

未纳入本提交：`.workbuddy/`、`batch_fbx_exporter_ExtraUV/`（无关）。

## 3. 关键结论 / 验证

- 本机 Secure Boot 下：**不要依赖 AppInit 全局钩子**长期挂着；Launch 路径只是短暂启用 hook 以便 Headless 加载，成功后会 `StopGlobalHook`。
- 若 Headless 已在跑，需先关掉再试，否则可能挂到旧实例 / 超时。
- 注入/Launch 成功后应看到 target control ident 落在合法端口范围。

## 4. 已知遗留

- Secure Boot + 未签名 shim：纯 Global Hook 对普通 GUI 进程仍可能完全无效。
- 若 MuMu 版本改名进程（非 `MuMuVMMHeadless.exe`），需再改匹配串。
- TinecmaTool 品牌化未保留在本分支 tip；需要时另开 branding 分支叠上去。
- 可选后续：进程监视自动 inject，减少对短暂 global hook 的依赖。
